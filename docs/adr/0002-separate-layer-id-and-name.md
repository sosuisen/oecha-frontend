# ADR-0002: レイヤーの識別子と表示名を分ける

作成日: 2026-09-18
状態: 採択

## 文脈

- レイヤーには今、`id` しかない。`'Layer01'` のような文字列を、内部の識別と画面の表示（`Info`）の両方に使おうとしている。
- ID は将来、サーバーや他の参加者との同期に使う。参加者ごとに一意でなければならないため、ハッシュ値を用いる予定である。
- ハッシュ値は人が読めない。画面には「Layer 01」のような人が読む名前を出したい。
- 1 つの文字列に「一意性」と「読みやすさ」の両方を求めると、どちらかを犠牲にすることになる。

## 決定

- `Layer` に `id` と `name` の 2 つのフィールドを持たせる。
- `id` は内部の識別子である。参加者間で一意であることを保証するため、将来はハッシュ値にする。画面には出さない。
- `name` は画面に表示する名前である。当面は「Layer 01」「Layer 02」の固定値とし、ユーザーによる変更は扱わない。
- 表示（`Info` など）は `name` だけを参照する。同期や検索など内部の処理は `id` だけを参照する。
- `name` から `id` を導出したり、その逆をしたりしない。両者は独立した値として `Layer` の生成時に与える。

## 検討した代替案

- `id` だけを持ち、表示時に加工する
  - 利点: `Layer` のフィールドが増えない。
  - 欠点: ID がハッシュ値になった時点で、加工しても人が読める名前にならない。表示の都合が ID の形式を縛る。
  - 不採用の理由: ハッシュ値への移行と両立しない。
- `id` を人が読める名前にし、そのまま表示する（現状の延長）
  - 利点: 最も単純で、今のテストがそのまま通る。
  - 欠点: 参加者間で一意にできない。「Layer 01」は全員が持つ名前になる。
  - 不採用の理由: 同期の要件を満たせない。

## 確信度

- 中程度。ID と表示名を分けること自体は一般的な設計であり、覆る可能性は低い。
- ただし `name` を `Layer` に直接持たせる形は、表示名をユーザーが変えられるようにした時点で見直す。そのとき、`name` を `Layer` に置いたままにするか、レイヤーとは別の設定（参加者ごとの表示設定など）に移すかを再検討する。
- レイヤーの同期そのものをやめた場合も、この決定の前提が崩れるので見直す。

## 影響

- 良い点: 表示の文言を変えても内部の識別に影響しない。ID をハッシュ値に変えるとき、表示側のコードを触らなくてよい。
- 良い点: テストで `id` と `name` を別々に検証できる。
- 注意点: `Layer` を生成する箇所（`TextureLayerStack`、`CanvasLayerStack`、各テスト）すべてで `name` を渡す必要がある。コンストラクタ引数が 1 つ増える。
- 注意点: `name` は一意ではない。名前でレイヤーを探すコードを書いてはならない。
- 中立: 当面 `id` は `'Layer01'` のような固定文字列のままである。ハッシュ値への移行は別の作業になる。
