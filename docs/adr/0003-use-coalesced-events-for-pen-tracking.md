# ADR-0003: ペンの追従には getCoalescedEvents を使う

作成日: 2026-09-26
状態: 採択

## 文脈

- ペンタブレットで速く線を引くと、線が折れ線に見える。
- `pointermove` はブラウザの描画フレームごとに 1 回しか発火しない。60Hz の画面なら 1 秒に約 60 回である。
- Wacom などのタブレットは 1 秒に 133 回から 200 回ほど座標を送る。フレームの間に届いた座標は 1 つの `pointermove` に合体され、イベントには最後の座標だけが残る。
- `PenCommand` と `EraserCommand` は `pointermove` ごとに 1 点だけ記録し、直前の点と直線でつないでいる。点の間隔が広いことが折れ線の原因である。
- レンダラーを WebGPU と Canvas で切り替えて比べたが、折れ線の度合いは変わらなかった。原因は描画側ではなく、点の取り方にある。

## 決定

- `pointermove` を受け取ったとき、`PointerEvent.getCoalescedEvents()` で合体された座標をすべて取り出し、その数だけストロークに点を記録する。
- 展開は `EventRouter` の `pointermove` ハンドラで行う。`PenCommand` と `EraserCommand` は変更しない。
- `getCoalescedEvents()` が存在しないか空配列を返す環境では、元の `pointermove` イベント 1 つをそのまま使う。
- ブラシカーソルの位置は、合体前のイベント（最後の座標）で 1 回だけ更新する。

## 理由

- 合体イベントは「実際にペンが通った点」である。推測ではなく実測の点が増えるので、線の形が正しくなる。
- `getCoalescedEvents()` は W3C Pointer Events 仕様の DOM API であり、Chrome、Firefox、Safari、Edge の現行版で使える。追加のライブラリは不要である。
- `EventRouter` は生の DOM イベントを受けているので、PixiJS の `FederatedPointerEvent` から `nativeEvent` を取り出す手間がない。
- 展開を `EventRouter` に置くと、ペンと消しゴムの両方に 1 か所の変更で効く。
- 空配列のフォールバックがあるので、jsdom 上の既存テストはそのまま通る。
- Windows 11 の Firefox と Wacom タブレットで確認し、速く引いた線の折れ線が目立たなくなった。

## 検討した代替案

- `PenCommand` と `EraserCommand` の `onPointerMove` の中で展開する
  - コマンドが自分で点を増やせるが、2 つのコマンドに同じコードが要る。将来コマンドが増えるたびに重複する。
- 点と点の間をベジェ曲線などで補間する
  - 点の数を推測で増やす方法である。実測の点を増やす `getCoalescedEvents()` を先に入れるべきで、それでも足りないときに追加する。両者は排他ではない。
- レンダラーを WebGPU に切り替える
  - 試した結果、折れ線の度合いは変わらなかった。原因が描画側にないので、対策にならない。

## 影響

- 良い点: 速く引いた線が滑らかになる。実装は `EventRouter` の数行に収まる。
- 注意点: 1 回の `pointermove` で `drawLine` が 2 回から 4 回呼ばれる。RenderTexture への焼き込みなら問題ない量だが、描画が重くなったときは最初に疑う場所である。
- 注意点: 将来ズームやパンを入れると、合体イベントの座標も変換する必要がある。展開が `EventRouter` の 1 か所にあるので、変換もそこにまとめられる。
- 見直す条件: 合体イベントを使っても折れ線が残るなら、ベジェ補間を次の ADR として検討する。
